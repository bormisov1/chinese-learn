01 · Drivers

Architecture invariants

1Local write first

Action, event, and outbox commit atomically. Network never gates studying.

2Union, never replace

Snapshots merge. Backend-missing local records are inventoried and uploaded.

3Immutable facts

Reviews/attempts are deduplicated events; SRS and counters are repairable projections.

4Deterministic merge

HLC, device, and mutation IDs form total order; identical inputs always converge.

5Soft deletion

Tombstones replicate 400 days. Hard deletion only through verified privacy erasure.

6Content-free metrics

No words, sentences, answers, OCR/clipboard content, filenames, or secrets.

Safety invariant: logout, account switching, sync reset, expired cursor, migration failure, and backend outage never silently delete local data.

05 · Lossless sync

Write → push → merge → pull → audit

Commit locally

Projection + fact event + outbox in one transaction.

Push idempotently

≤100 mutations / 512 KiB, oldest first.

Merge server

Validate, dedupe, resolve, sequence canonical changes.

Pull cursor

Apply page + cursor atomically to a stable head.

Reconcile

Login, restore, expiry, anomaly, and every 30 days.

Missing-record detection

Local live, absent server

Enqueue complete upsert, including legacy records created before outbox support.

Server live, absent local

Download and merge. Absence is never deletion.

Both differ

Deterministic merge; upload repair when merged result differs.

Tombstone conflict

Later total-order clock wins; newer live edit explicitly resurrects.

06 · Authentication

Telegram, Google/Gmail, or password—one account

Telegram OIDC

Current authorization-code flow + PKCE S256. Exact redirect, one-time state/nonce; verify signature, issuer, configured audience, expiry/not-before, code single use. Use immutable sub. Legacy widget only during migration, with server HMAC + ≤5-minute freshness.

Google OIDC

Authorization Code + PKCE S256; validate signature, issuer, audience/authorized party, nonce, times, state, exact redirect. Scopes only openid email profile; no Gmail mailbox access.

Email + password

12–256 chars; allow paste/managers. Argon2id initial target 64 MiB ×3, p=1, benchmarked; unique salt and optional KMS pepper. Breached/common check, generic errors, layered throttles.

Email confirmation: pending account; 32-byte random single-use token; store keyed digest only; 30-minute expiry; resend invalidates old tokens. Pending users cannot sync or link.

Safe linking

Authenticated session + fresh proof. Never auto-link on equal email. Collision requires authentication to both accounts and transactional idempotent merge.

Sessions

10-minute memory access token. Rotated opaque refresh token in Secure/HttpOnly/SameSite cookie or native secure store. Reuse revokes family.

Recovery

Generic response; 15-minute one-use reset token. Reset revokes refresh families and sends security notice.

09 · Trust

Security and privacy

Application

TLS 1.2+, HSTS, exact CORS, CSRF, CSP, size/depth/rate limits, parameterized SQL, output encoding, supply-chain scanning.

Secrets

Managed secrets/KMS, environment-separated rotating keys, envelope-encrypted DB/backups, audited break-glass.

Authorization

User only from session; strict UUID/range/enum schema. Private DB, least-privilege RBAC, JIT audited production access.

Safe logs

Request ID, route template, status, latency, bytes, pseudonyms. Never body, token, email, word/sentence/answer/OCR/clipboard/key.

Privacy lifecycle

Export, correct, unlink, delete. Disable login, reversible 30-day deletion window, scheduled purge and minimized audits.

Abuse defense

Enumeration resistance; IP/account/device throttle; OAuth CSRF/replay defense; refresh reuse detection.

10 · Operations

Observe, deploy, migrate, roll back

SLOs

Auth/sync 99.9%; accepted mutation durability 99.999%; p95 batch <500ms; 99% online convergence <60s.

Signals

Outbox age/size, accept/reject/dedupe, cursor lag/expiry, missing-local repairs, conflicts, drift, DB/worker/email.

Alerts/tests

Burn rate, mutation-loss invariant, outbox >10m, hash mismatch, drift, backup failure. Synthetic offline→two-device convergence.

Recovery

Multi-AZ + PITR; daily encrypted cross-account/region backup; quarterly restore. RPO ≤5m, RTO ≤60m.

Safe evolution

Expand

Add compatible nullable structures/readers.

Migrate

Checkpointed online backfill; copy-on-write client.

Dual mode

Dual read/write under flags; validate hashes/counts.

Canary

1→10→50→100%, keep rollback compatibility.

Contract

Only after supported client/recovery window.

Local migration: checksum hanzi-deck:v1 → timestamped recovery copy → copy-on-write database migration → validate IDs/counts/references/projections → atomic pointer flip. Never auto-delete the source. Failure reopens it.
Acceptance gates
  • Legacy local record absent server is discovered and uploaded.
  • Concurrent offline reviews preserve both facts and reproduce identical SRS.
  • Duplicate/reordered requests are idempotent; cursor paging is crash-safe.
  • Logout/account switch never deletes data; local stores are account-namespaced.
  • Secrets/content cannot enter telemetry or logs under schema/fuzz tests.
  • Failed migrations roll back without losing a mutation.
  • Restore/replay meets RPO/RTO; current and previous two clients coexist.
